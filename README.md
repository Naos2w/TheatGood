# TheatGood

**台灣影廳 3D 座位視角預覽與個人觀影紀錄 App**

以 Vue 3 / TresJS 開發的**台灣影廳座位視角模擬器＋個人觀影足跡 App**。核心是利用影廳座號、走道、銀幕大小與估算的空間幾何，在 2D 選擇座位並預覽第一人稱 3D 銀幕視角；也讓使用者**自由輸入看過的電影、日期、影廳、座位**，日後回顧自己的觀影足跡。**不需要真實放映場次、不查驗電影是否存在或上映過，也不做評分、心得、社群或即時訂票。**

> **2026-11-16 產品範圍：** 優先補齊威秀／秀泰／美麗華／美麗新的真實座位配置與銀幕幾何，同時已完成「手動新增／回顧觀影紀錄」的**瀏覽器本機 MVP**。此版本不需電影上映／場次驗證、不使用後端資料庫，也不會跨裝置同步。既有場次頁／API 是選用補充，未取得完整座位圖前不以席數創造假 3D。完整計畫見 [TODO](TODO.md)。

## 目前可使用（P0 + P1 部分功能 + v2 UI）

- **連鎖影城搜尋優先＋百貨名稱＋影廳特色＋視角一致性（開發版）**：首頁的「附近影城」定位按鈕移回搜尋欄旁，使用者點擊並授權後依分館場址直線距離排序；主要搜尋只顯示確實已有可操作座位圖的連鎖影城（現階段 22 個威秀／MUVIE 分館，其他品牌留待取得座位圖才顯示），取消「可查看座位」、移除文化／獨立影廳的首頁分類但保留原始資料與深連結。優先以官方資料可核對的**百貨／商場名稱**作標題，附威秀官方 favicon 圖示與分館品牌顏色；影廳特色可依已發布的**分館層級** IMAX（7）、TITAN 巨幕（2）、4DX（4）篩選，但**不推斷每個廳號就是該格式**，3D 檔期則依上映場次無法當成永久廳別。參考 [Apple Design Skill](https://github.com/MrRoam/apple-design-skill) 之「內容優先、簡明分類、玻璃限於功能層」。同時修正 2D 銀幕線與 3D 場景原本分別用 94%／86% 座位區寬度假設的落差，統一採 86% **未實測的概念比例**；威秀 3D POV 固定視角由 80° 改為 65°，畫面放大但**並非修改真實銀幕尺寸或完成 1:1 校準**。詳見 [首頁與 3D 比例稽核](docs/apple-design-discovery-and-screen-pov-2026.md)。此改版**只進 develop，不發布 staging／main 或 1.0.0.0**。
- **液態玻璃透視及小螢幕邊界修正（開發版）**：修正只有磨砂白卡片、內容不會從背後透出的問題：固定頂部導覽使內容在捲動時位於玻璃後方；將導覽、手機底部選單、3D 視角操作條改為較低不透明度、適度 `backdrop-filter`、內外側高光邊緣和隨指標移動的細緻反光（Web CSS _近似_ Liquid Glass，不冒稱原生 Apple 光學折射）。修正 320px 手機的連鎖影城名稱遭兩個右側操作鈕擠壓，改成整張列表卡片可直接點選，地圖鈕獨立；手機／桌面固定導覽與設定面板不超界、選位操作條在窄屏不遮斷。座位圖因須保持座號可讀，允許**僅水平滑動**，取消內部垂直捲動以避免雙層捲軸。尊重降低透明度、降低動態與不支援 backdrop-filter 的回退。**只在 `develop`，原 UAT／正式版不變。**
- **iOS 風格極簡 UI／UX（開發版）**：以「選影城 → 選影廳 → 點座位 → 看 3D」為唯一主要流程；頂部／手機底部選單改成半透明模糊玻璃面板，保留淺色、深色、無動態／降低透明度的回退。常用導覽只保留「找影廳／觀影足跡」；首頁將排序與定位放進「更多選項」。分館影廳卡片一點即進 2D 選位，手機選位時固定顯示座位／3D 操作列。**銀幕尺寸、排距、坡度、來源比對與鏡頭 FOV 等技術數據繼續留在模型、單元測試和開發稽核文件，使用者介面不再公開調整或顯示**；視角仍簡短註明是模擬，不宣稱 1:1 實拍。沒有變更原始座位、3D 資料或觀影紀錄。此 PR **只進 develop，不變更 staging／main、不發布 1.0.0.0**。

> **發布決策（2026/11/17）**：既有 `staging` UAT 版本維持不變，`main` 正式環境不發布；後續功能先在開發分支完成並經 PR 整合 `develop`。**1.0.0.0** 只有在使用者明確驗收並批准發布後，才可經 `develop → staging → main` 的既有晉升流程。不可因 CI 通過或先前 UAT 驗收而自動部署新版。

- **整合影城類別篩選（開發版）**：首頁共用「全部／連鎖影城／文化與獨立影廳」分類、關鍵字、地區與模型可用性篩選。預設連鎖分館優先、文化影廳在後；已確認的 5 個文化／獨立場館及 9 個影廳也可獨立篩選，現有 2D／3D 入口與官方資料來源不變。舊版信義威秀第 12 廳保留在連鎖影城，不重複歸類文化影廳。
- **座位圖置中與影城地圖連結（2026/11/17）**：分館 2D 座位參考圖與 3D 選座頁使用相同的版面換算，依座位／輪椅標示真正佔用的最左、最右欄置中，排除訂票表格多餘的空白欄；桌面置中顯示、手機可水平捲動並預設置中。連鎖影城的地圖按鈕不再打開 OSM 原始座標來源，而是桌面開 **Google Maps**、Android 使用 **geo:** 連結交由已安裝地圖 App 處理、iOS 開 Apple Maps 網頁／App（視系統支援），並在手機分館頁提供 Google Maps 備用連結。瀏覽器無法查詢或保證使用者自訂的地圖預設 App。
- **統一「影城 → 影廳 → 座位 → 3D」導覽（2026/11/17）**：首頁直接說明 22 個威秀／MUVIE 分館、222 種已收錄座位配置，並在「可預覽 3D」篩選中納入這些分館；點選分館後可由影廳卡片切換來源座號、走道與可用的估算 3D，未配對廳號會標示「座位圖待補」。選位頁可直接切換同分館其他影廳，返回分館時保留原廳號。首頁原本優先連到信義第 12 廳 234 席的影展舊版，現已改為**較新的 244 席公開場次座位圖**；舊版保留獨立連結與清楚提示，避免誤認它是唯一建模的影廳。未合併資料仍不冒稱精確 3D。
- **3D 影廳場景視覺升級（概念模型）**：既有威秀／MUVIE 222 種座位配置與文化場館 3D 共用的 Three.js 影廳引擎，已加入立體椅背／椅墊／頭枕／扶手、分層階梯、座位缺口、概念吸音牆與天花板、低亮度走道引導燈及原創程序繪製的銀幕投影。選位後可切換「座位 POV」與「全廳 3D 概覽」，也能拖曳環視及切換相鄰座位。數百張椅子改以 **6 組 InstancedMesh 批次渲染**，減少繪圖負擔。**座椅材質、牆面、燈光、階梯與銀幕影片畫面均為原創視覺假設，不是影城提供的現場照片或實測設備圖**。各廳真實座號與比例校準仍遵守原來源標記。
- **威秀 2D × 銀幕寬度比例校準（估算）**：當同一影廳有來源化銀幕寬度時，以真實座位格線跨距、銀幕寬度和**可調的銀幕／座位區寬度比例假設**推算橫向格距；沒有銀幕尺寸時仍使用明示可調的格距概念值。訂票格線不是已驗證等比例建築圖，所以即使已知銀幕大小，也**不能精確換算深度、坡度或實際觀看距離**。公式及精度界線詳見[3D 規格文件](docs/auditoriums/vieshow-3d-specifications-and-estimates-2026.md)。
- **全台威秀／MUVIE 3D 座位視角概念模擬（2026/11/17）**：上述 222 種逐廳 2D 座位資料都能進入可操作的 Three.js／TresJS 3D 影廳；支援完整原座號、輪椅位置、走道缺口、同排相鄰座切換、滑鼠／手機拖曳環視、視角 65°／80°／95°，並可調整座距、排距、坡度與首排距離。**實際可用銀幕尺寸**目前以台北松仁 TITAN（官方 22 × 12m）及板橋 IMAX（尚未官方核實的第三方 21.33 × 11.46m）為明確來源範例，其他銀幕比例均為概念估算；**不是實測 1:1、不可視為「最佳座位」結論，也不自動連結個人觀影足跡**。詳見[規格來源與 3D 假設](docs/auditoriums/vieshow-3d-specifications-and-estimates-2026.md)。
- **全台威秀／MUVIE 官方座位圖參考資料（2026/11/16）**：已從 22 個分館公開場次蒐集並去重 **222 種逐廳 2D 座位配置**，保留座號、相對座位格線、走道缺口、輪椅標示與原始來源；其中 **205／229 筆官方公布數字廳**已直接對到廳號，**187 種座位數相符、18 種座位數有差異、17 種尚無對應官方席數**。每間分館只載入自身座位資料，數字座號／GC／字母廳原樣呈現；不儲存即時票況。**尚未量測的銀幕尺寸、排距與坡度不能冒稱精確 3D**。詳見[全台蒐集稽核](docs/auditoriums/vieshow-national-public-seat-layouts-2026.md)；信義第 6／11 廳的[原始核對](docs/auditoriums/vieshow-hsinyi-public-seat-layouts-2026.md)仍保留。

## 本機啟動

需 Node.js 22.12+（建議 Node.js 24）與 npm。

```bash
npm install --include=dev
npm run dev
```

用瀏覽器開啟 Vite 顯示的地址（通常為 `http://localhost:5173`）。

```bash
npm run schema:generate # 從 Zod 型別產生 public/schemas/auditorium-v1.schema.json
npm run typecheck
npm run lint
npm run test
npm run build
npm run format:check
npm run db:screenings:sync # 選用：只讀預覽舊版官方電影場次；非核心需求、不連線／不修改資料庫
```

若全域 npm 設定了 `omit=dev`，使用 `npm install --include=dev` 才會安裝 TypeScript、Vitest、ESLint 等開發工具。單純瀏覽現有 2D／3D 仍**不需要 Neon、Google 登入或 API Key**；執行資料庫 Migration、Seed 或伺服器端目錄 API 時才需要後端 DATABASE*URL，且**不得**使用 VITE* 前綴。

## 檔案架構

- `src/features/auditoriums/schema.ts`：Zod 資料驗證與跨欄位檢查。
- `src/features/auditoriums/tfai-small.json`：小影格的來源資料與估算幾何。
- `src/features/auditoriums/spot-taipei.json`：光點台北的官方 83 席座位編號與估算幾何。

- `src/features/cinemas/chain-directory.ts`：40 個四大品牌商業連鎖影城分館與官方來源，和影廳／座位模型分層維護。
- `src/features/cinemas/vieshow-halls.ts`：威秀 2026 年官方逐廳座位數快照（229 筆）。
- `src/features/cinemas/other-chain-facts.ts`：秀泰、美麗華、美麗新官方公開的影廳總數、局部區域、特色格式及美麗華逐廳席數，保留數值所屬範圍與來源，不包含座號、3D 幾何或售票庫存。
- `src/features/cinemas/official-showtimes.ts`：40 間分館的官方場次外部入口與品牌／分館範圍，不含場次 Feed、座位庫存或購票 API。
- `src/features/auditoriums/directory.ts`：既有 9 間影廳、別名搜尋及資料可信度分級。
- `api/screenings.ts` 與 `src/features/screenings/`：文化部電影開放資料的唯讀 API、場次正規化與前端查詢頁。
- `src/features/auditoriums/demo.ts`：虛構示範影廳。
- `src/features/auditoriums/catalog.ts`：只有確實有 3D 模型的可選座清單（含 DEMO）；其餘影廳只顯示官方資訊。
- `src/features/auditoriums/geometry.ts`：座位座標與視角計算。
- `src/features/viewer/`：3D 場景、Viewer UI、相機。
- `src/components/SeatMap.vue`：依座標產生的 2D 座位圖。
- `src/stores/viewer.ts`：選位及相機模式。
- `docs/auditoriums/`：各影廳官方來源、精度與使用限制。

單位統一為公尺，Y 軸向上，銀幕位於 z=0、面向 +Z；各座位坐標由同一套資料產生。新增真實影廳時，須同時附上來源、查證日期及官方／估算欄位標記。

## 分支與 CI

- `develop`：Dev，日常功能整合（功能 PR 經 Squash Merge）。
- `staging`：UAT，只接受 `develop` 晉升 PR（使用 Merge commit）。
- `main`：Production，只接受 `staging` 晉升 PR（使用 Merge commit）。
- GitHub Actions 僅在 PR／手動觸發；純文件 PR 不安裝依賴，合併後不重跑 CI。
- Vercel 採單一專案：`develop`（Dev Preview）、`staging`（UAT Preview）、`main`（Production）；功能分支不自動部署，純文件變更跳過建置。
- Vercel `vercel.json` 支援 Vue Router 深層網址（SPA Rewrite），UAT 人工驗收後才晉升正式環境。

完整分支保護、GitHub Runner／Vercel 節流與發布規則請見 [分支與 CI 規範](docs/branching-ci.md)。

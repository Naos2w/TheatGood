## 2D 平面座位圖 × 銀幕寬度的比例校準

優先採用「來源化銀幕寬度＋官方 2D 座位格線」建立**水平相對比例**，而不會只依總席數平均分配假座號。

1. 從官方座位圖保留所有座號的相對欄位與走道缺口，計算最左到最右（含輪椅位置）的座位區橫向格數 `C`。
2. 若該廳有可引用的銀幕寬度 `W`（公尺），設定一個**可調的假設比例** `R = 銀幕寬 ÷ 座位區寬`，初始暫用 `R = 0.86`；推算座位區寬度 `W/R`，再推算水平格距 `W/(C×R)`。例如銀幕寬 22m、座位區 32 格時，初始格距約 0.80m、座位區約 25.58m 寬。
3. 若沒有銀幕真實寬度，仍以 2D 格線結構為準、以可調格距 0.66m 作概念場景，不假稱已取得公尺比例。銀幕寬高同樣只能以此格距與假設比例估算。
4. **最重要的限制**：公開訂票座位圖通常是為辨識座號而繪製的**示意格線**，其「銀幕位置」示意線不一定與座位網格按相同比例繪製。現有資料尚未能證實 `R`，因此**就算銀幕寬度是官方值，座位區的公尺寬與水平格距也都是估算**。使用者可調 `R` 比較視角敏感度，未來若取得有比例尺的建築平面圖才將這個比率升級為可引用校準。
5. 銀幕寬度只有**水平**尺度錨點，不能反推出首排距離、前後排距、地面坡度、銀幕高度位置、斜角與可視遮擋；這些仍由獨立參數控制，並保留來源精度標記。任何座位視角角度與公尺距離皆為模型推算值，不代表現場實測。

## 3D 模型外觀與裝置效能（概念視覺升級）

原本用兩個方塊代表座椅的模型已更新為多部分的原創座椅造型：椅背骨架、靠墊、頭枕、坐墊、扶手與扶手墊。為避免 391 席的 TITAN 影廳產生數千個獨立 Draw Call，所有座椅零件以 **6 組 InstancedMesh** 繪製（8 個可見部件／座位，391 席共 3,128 個零件實例，而非 3,128 個獨立 draw calls）。可以在相同座號下切換第一人稱座位視角與後方全廳概覽，後者用於檢視座位分布、區域缺口及空間佈置。

影廳新增連續分層地板與階梯立面、座位圖缺口的暗色地板帶、兩側柔和引導燈、吸音牆面與天花板裝飾，以及由程式繪製的原創抽象投影畫面（不是任何電影的截圖／影廳官方照片）。3D 的視覺造型與色彩是**一般性的美術假設**，不代表某間影廳實際使用的椅型、材質、照明設備、牆板與天花板。訂票座位格線缺口也不必然是正式消防動線，不能以概念模型作為出口與無障礙資訊。

場景中的階梯高度仍來自使用者可調的模擬坡度，銀幕寬高維持既有來源級別，不把概念內裝視覺效果錯誤提升為真實尺寸證據。無 WebGL2 時仍保留原 2D 資料模式。

## 驗收與操作

從一間威秀／MUVIE 分館開啟公開 2D 座位表，切換廳號，按「進入座位 3D 視角模擬」：

1. 在原創 2D 座位格線點位或從清單選擇實際存在的座號；沒有來源的空白格與輪椅位置不作普通座位。
2. 進入全螢幕 3D，拖曳左右環視、相鄰座位切換，並可調 65°／80°／95° 水平 FOV。
3. 返回 2D 時保留座位選擇；有銀幕來源時調整「銀幕／座位區寬度比」推算座位橫向間距，沒有來源則可調概念格距；前後排距、坡度、首排距離始終保持可調。所有調整只影響 3D 幾何，**已公布的銀幕寬高不會改動**。
4. 無法使用 WebGL2 的裝置保留 2D 座位圖／來源資料，不假裝已顯示 3D。
5. 不因估算 3D 模擬而將影廳自動綁定個人觀影紀錄；歷史座位足跡仍需一致且版本化的正式來源模型。

下一階段需要取得各廳現場平面圖、銀幕寬高、首排距離、坡度／曲面等可驗證資料，優先清理剩餘 24 個廳號未配對與 18 個容量差異的紀錄。秀泰 App 截圖僅用於交互功能比較，沒有複製其畫面或「黃金視角」結論。
